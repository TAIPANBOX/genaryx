## Architecture positions (decided; do not re-litigate)

1. **Remote transport is WireGuard-primary, SSH for ops (D11).** The draft roadmap 09 said SSH; the deployment decision supersedes it: Genaryx brings up its OWN userspace WireGuard peer (bundled `wireguard-go`, cross-platform, no kernel extension) to the client-hosted Cloud, which is then reachable ONLY inside the tunnel - never exposed to the internet. WG is the CHANNEL (who can connect at all); the existing ES256 device-signing stays the MESSAGE layer (who signed which action). WG is additive, never replaces signing. SSH stays for ops/remote-tail (`tail -c +off -F` over SSH) and the descriptor read. Mobile stays TLS+signing for now (WG-on-iOS is a later, optional enhancement).
2. **The remaining four planes are read/tool panels, no new backend.** Quality/Verdryx, Crypto/Qryx, Drills/Mockryx are pure CLIs; Memory/Engram is an MCP stdio server. The console shells out to their CLIs (a `ToolRunner`) or speaks MCP stdio (Engram), parses their JSON, and renders - exactly the "console composes existing APIs" principle. Each is a connector in `crates/connectors` + a panel in both shells, mirroring the Money/Policy/Identity waves.
3. **Evidence Center assembles, it does not compute.** ~80% of compliance is already built in the primitives (Cloud audit chain + compliance evidence, Qryx ML-DSA evidence, FOCUS export, Agent-BOM/CBOM). W3 packages them into one zip with a manifest + a `console_evidence_built` bus event; it never re-implements a compliance check.
4. **Hetzner is read-only, v1.** A read-only inventory connector (taipan-tagged servers, status, price/hr) so a campaign's boxes are visible in the console. The console never creates or deletes Hetzner resources.

### Verdryx (quality) - grounded from `~/Development/verdryx` (**PYTHON**, not Go/Rust)

So the `VerdryxClient` does NOT shell out to a CLI for data - it **reads `verdryx.db` (SQLite) directly** (the console already links rusqlite for its own Store) and/or the `verdryx.*` bus events. ### Engram (memory, MCP stdio) - grounded from `~/Development/engram` (**PYTHON**, `engdbram` on PyPI, not Go)
- The Memory panel drives the **`engram-mcp` stdio server** (the official Python `mcp` SDK / FastMCP), the console's FIRST MCP-client connector.
